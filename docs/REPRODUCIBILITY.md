# Reproducibility guide

## 1. Environment

Use Python 3.10 or newer. Install dependencies with:

```bash
python -m pip install -r requirements.txt
```

Run the synthetic tests before processing measurements:

```bash
python -m unittest discover -s tests -v
```

## 2. Build the audited dataset

Place the nine files listed in `data/README.md` under `data/raw/temperature/`, then run:

```bash
python scripts/build_experimental_dataset.py \
  --raw-dir data/raw/temperature \
  --output-dir data/processed
```

Expected v1 quality-control totals are 41,599 parsed rows, 41,578 rows within the defined sensor ranges, and 21 invalid rows on 3.22. A mismatch means the input files or parser version differ from the audited snapshot.

The processed table preserves the original `M.D` label but also adds an ISO `experiment_date` field. On 2026-03-17, the recorded wall-clock duration is 4.4418 h while the reconstructed fifth-channel duration is 1.6255 h; therefore `logger_time_s` must not be assumed to be a synchronized wall clock.

## 3. Build the electrical dataset

Place the nine instrument Markdown exports under `data/raw/electrical/`. If available, place the four original XLSX files under `data/raw/electrical_xlsx/`, then run:

```bash
python scripts/build_electrical_dataset.py \
  --power-dir data/raw/electrical \
  --xlsx-dir data/raw/electrical_xlsx \
  --output-dir data/processed
```

Expected totals are 162,844 rows, 162,840 rows passing electrical range and `P ~= V * I` checks, and four inconsistent rows on 2026-03-22. The four XLSX/Markdown pairs should have equal row counts, timestamps, voltage, current, and active power.

## 4. Diagnose electro-thermal alignment

```bash
python analysis/diagnose_electrothermal_alignment.py \
  --thermal-csv data/processed/experimental_clean_v1.csv \
  --electrical-csv data/processed/electrical_clean_v1.csv \
  --raw-thermal-dir data/raw/temperature \
  --output-dir results/alignment \
  --bin-seconds 30
```

The script estimates the normal thermal sampling period from the timestamped 2026-03-17 record (expected median 5.834 s). It retains recorded timestamps on that day; on the other days it reconstructs a fixed-period clock and anchors the final thermal record to the final electrical timestamp, following the confirmed acquisition sequence. It writes:

- all candidate scores and separated top candidates;
- a JSON diagnostic including +/-30/60/120 s sensitivity;
- `thermal_clock_reconstruction_v1.csv` with row-level clock provenance;
- `electrothermal_aligned_30s_v1.csv` with common 30 s bins; and
- two 300 dpi figures.

Candidate ranking combines irradiance-power rank agreement and cloud-event agreement, but is diagnostic only. It cannot overwrite recorded timestamps or the acquisition-process anchor simply because another offset has a higher correlation. File modification times are retained only as independent forensic context.

## 5. Run whole-day baselines

```bash
python analysis/fit_panel_temperature_models.py \
  --dataset data/processed/experimental_clean_v1.csv \
  --output-dir results/panel_temperature_baselines \
  --step-s 10
```

Each experiment day is held out in turn. Report per-day errors before any aggregate mean because weather, initial conditions, flow setting, and experiment duration vary substantially across days.

## 6. Evidence rule

Only files regenerated by the commands above belong to this repository's evidence chain. Historical competition figures and simulations are outside scope unless separately audited and imported with provenance.
